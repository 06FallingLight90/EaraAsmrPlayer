## 踩坑记录（新）

### 1. 无 BOM 的 .ps1 临时脚本含中文注释 = PS 5.1 按 ANSI(GBK) 误读，代码可能被字节吞噬变形执行

- **现象**：首个 A2 脚本报「package 行已改 5 文件」但后续行为诡异；另一个脚本直接 ParserError 在不存在的 `}`。
- **根因**：Write 工具写 UTF-8 无 BOM；PS 5.1 对无 BOM .ps1 按 ANSI 读，中文注释的 UTF-8 字节被 GBK 两两配对误读，可能吞掉引号/大括号/换行，**改变代码语义而不报错**（最危险）或报错（幸运）。
- **解法**：临时 .ps1 一律**纯 ASCII 注释**（或显式写 BOM）。已全量重写三个脚本为 ASCII。

### 2. 并发写入：工作区出现非本会话改动

- **现象**：ci.yml 被删守护步骤、ValueCipher 被改 internal、NetworkModule/文档被改，且 review 报告文件会话中途出现；13:10 同一秒批量写入。
- **根因**：用户另一个任务会话同时在改本仓库。
- **处置**：用户确认无实质内容后 `git stash push`（留证可恢复）回到干净树重做。**教训：动 git 前先 `git status` 全量核对，发现计划外改动立即停下问用户，不要默默混入提交。**

### 3. Kotlin 编译错误日志捕获的两个坑

- 后台 job 的 output.log 有 ~120 字符宽度折行（同 Out-File 坑），错误行截断丢符号名 → 重跑时 `| Out-File -Width 1000`。
- 错误行格式实为 `Unresolved reference: name`（冒号紧贴，无空格），且 Windows 路径要 `file:///([A-Za-z]:/[^:]+):(\d+)`（盘符冒号会吃掉 `[^:]+` 的通配）。

### 4. 编译器引导补 import 的注入器要点（tools 思路可复用）

- 符号清单靠 inventory 脚本抓列 0 声明，**会漏**：扩展 receiver（`fun X.name()` 抓成 X）、`const val`、注解同行声明 → Find-Fq 需三类正则兜底（普通/类型/扩展+const）。
- 同名成员遮蔽 import 顶层函数的重载错误（`Cannot find a parameter with this name` / `No value passed for parameter 'model'`）不是 Unresolved，注入器抓不到 → 补 import 后成员与顶层按适用性正确分派。
- 后台任务被回收时注入脚本可能中断于文件写入之间 → 注入后必须以重新编译的结果为准，不轻信上次注入计数。
