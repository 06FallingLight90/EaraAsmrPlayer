## 踩坑记录（新）

### 1. 无 BOM 的 .ps1 临时脚本含中文注释 = PS 5.1 按 ANSI(GBK) 误读，代码可能被字节吞噬变形执行

- **现象**：首个 A2 脚本报「package 行已改 5 文件」但后续行为诡异；另一个脚本直接 ParserError 在不存在的 `}`。
- **根因**：Write 工具写 UTF-8 无 BOM；PS 5.1 对无 BOM .ps1 按 ANSI 读，中文注释的 UTF-8 字节被 GBK 两两配对误读，可能吞掉引号/大括号/换行，**改变代码语义而不报错**（最危险）或报错（幸运）。
- **解法**：临时 .ps1 一律**纯 ASCII 注释**（或显式写 BOM）。已全量重写三个脚本为 ASCII。

### 2. 并发写入：工作区出现非本会话改动

- **现象**：ci.yml 被删守护步骤、ValueCipher 被改 internal、NetworkModule/文档被改，且 review 报告文件会话中途出现；13:10 同一秒批量写入。
- **根因**：用户另一个任务会话同时在改本仓库。
- **处置**：用户确认无实质内容后 `git stash push`（留证可恢复）回到干净树重做。**教训：动 git 前先 `git status` 全量核对，发现计划外改动立即停下问用户，不要默默混入提交。**
- **stash 留证核查（2026-10-01）**：`stash@{0}`（37 文件）分两类——①32 文件为首次 A2 尝试的 import 重写，因 GBK 脚本损坏内容本身有错，已被干净重做（47a2ad4/225347e/d0c15f3）取代；②另一任务 5 处改动中，ci.yml 删守护步骤 / NetworkModule 改回 inline URL / ARCHITECTURE.md 与 devnote 删重构记录均为**反向改动**（撤销重构成果，不可应用）；唯 ValueCipher 改 `internal`（EncryptedValue/ValueCipher 收窄可见性）未入 HEAD 且符合封装方向，已向用户标记备选。结论：修改点均落在重构范围内，stash **保留**不 drop。

### 3. Kotlin 编译错误日志捕获的两个坑

- 后台 job 的 output.log 有 ~120 字符宽度折行（同 Out-File 坑），错误行截断丢符号名 → 重跑时 `| Out-File -Width 1000`。
- 错误行格式实为 `Unresolved reference: name`（冒号紧贴，无空格），且 Windows 路径要 `file:///([A-Za-z]:/[^:]+):(\d+)`（盘符冒号会吃掉 `[^:]+` 的通配）。

### 4. 编译器引导补 import 的注入器要点（tools 思路可复用）

- 符号清单靠 inventory 脚本抓列 0 声明，**会漏**：扩展 receiver（`fun X.name()` 抓成 X）、`const val`、注解同行声明 → Find-Fq 需三类正则兜底（普通/类型/扩展+const）。
- 同名成员遮蔽 import 顶层函数的重载错误（`Cannot find a parameter with this name` / `No value passed for parameter 'model'`）不是 Unresolved，注入器抓不到 → 补 import 后成员与顶层按适用性正确分派。
- 后台任务被回收时注入脚本可能中断于文件写入之间 → 注入后必须以重新编译的结果为准，不轻信上次注入计数。

## 用户报 bug 归因：切片循环仅前台生效（2026-10-01）

- **现象**：切片循环后台不检测，回前台立刻跳转。
- **根因**（子代理取证）：切片检测由 `PlayerConnection.kt:143-181` 的 Main 线程轮询驱动，每轮先 `awaitFrameCommit()`（:812，Choreographer 帧回调）——熄屏/后台无 vsync 帧回调，协程永久阻塞在帧等待上，切片判定停摆；播放本身（PlaybackService/ExoPlayer）不受影响，故回前台第一轮就补跳。
- **归因**：非本轮重构引入。`git log -S awaitFrameCommit` 仅命中 ddf3ab7（2026-08-01，v1.2.0 性能优化，把"读位置→判定→delay(250)"改为每轮等帧回调）；两轮重构 diff 均未触及 PlayerConnection 切片逻辑。
- **修复方向（用户已决策：留待后续重构彻底修复）**：把 `applySliceLoopIfNeeded` 从 `awaitFrameCommit` 阻塞中解耦（帧对齐只包快照更新），或下沉到 PlaybackService 用纯时间轮询。
- **上游 issue**：[#322](https://github.com/eValDoll/EaraAsmrPlayer/issues/322)（eValDoll/EaraAsmrPlayer，2026-10-01 提交；上游代码经 `upstream/main` 核实含相同逻辑）；修复计划在 B 阶段 service 边界重构时顺路做彻底版。
